# 場所検索（OpenPOI API）の実測

最終測定: 2026-10-03（UTC 04:00）。再現コマンド: `npm run probe:openpoi > probe.json`（`scripts/probe-openpoi.mjs`。標準出力だけに書き、リポジトリへは保存しない）。

## 目的

外部の場所検索を設計する前に、次の3点を実データで確かめる。

1. 返る候補の並び順と件数上限が、端末側の処理にどう影響するか。
2. 正確な位置を送らず丸めた位置で問い合わせたとき、近くの候補をどれだけ取りこぼすか。
3. カテゴリや座標などの項目がどの程度そろっているか。

## 方法

- 対象: 日本全国28地点（那覇から旭川までの主要駅・中心市街地。軽井沢・高山などの観光地を含む）。無作為抽出ではない。
- 1地点あたり `GET /v1/search` を7回、計196回。250ms間隔で順番に送信（公表上限 200 req/s を大きく下回る）。
- 半径100/300/1000m・上限50件の件数、上限50件の並び順、カテゴリ不明・座標なしの割合を測る。
- 正解（基準）は「正確な地点を中心に上限200件で取得し、正確な距離で近い順に並べた上位10件」とする。
- 丸めた問い合わせは、中心を小数第3位または第2位に丸め、半径を升目だけで決まる固定値（第3位は380m、第2位は1060m。正確な位置から計算した値は升目の中の位置を漏らすため使わない）、上限200件で取得し、端末側で正確な位置からの距離で並べ直した上位10件を正解と比べる（再現率）。
- 割合の区間は Wilson 95% 信頼区間。対応のある比較（第3位と第2位）は符号検定と対応のある差の t 区間で評価した。

## 結果

| 指標 | 値 |
|---|---|
| 応答時間（ブラウザ外、196回） | 中央値 35.3ms（四分位 31.8〜39.1ms、最大 210ms） |
| CORS | `access-control-allow-origin: *` |
| 上限50件・半径300mで件数が上限に達した地点 | 28/28（半径100mでも中央値50件） |
| 距離順に並んでいた地点 | 1/28（3.6%、95%CI 0.6〜17.7%） |
| 上限50件の結果と「近い順の上位50件」の重なり | 平均 0.944（中央値 0.96、最小 0.82） |
| 最寄り候補までの距離 | 中央値 8m（四分位 5〜15.5m、最大 40m） |
| カテゴリが `unknown` | 244/1400 件（17.4%、95%CI 15.5〜19.5%） |
| 座標なし | 0/1400 件（95%CI 0〜0.27%） |
| 小数第3位に丸めたときのずれ | 中央値 36.5m（最大 67m） |
| 小数第3位＋上限200＋端末で並べ直し: 上位10件の再現率 | 平均 0.961、中央値 1.0。完全一致 25/28（89.3%、95%CI 72.8〜96.3%） |
| 小数第2位に丸めたときのずれ | 中央値 425m（最大 656m） |
| 小数第2位＋同条件: 上位10件の再現率 | 平均 0.25、中央値 0。完全一致 7/28（25%、95%CI 12.7〜43.4%） |
| 第3位と第2位の対応比較 | 第3位が上回る 21、下回る 0、同点 7。符号検定 両側 p ≈ 9.5×10⁻⁷。差の平均 0.711（95%CI 0.538〜0.883） |

小数第3位で取りこぼしがあった地点: 渋谷 0.8、京都 0.9、三宮 0.2。いずれも狭い範囲に施設が密集し、上限200件が丸めた中心の近くで埋まった地点である。

## 限界・反証

- 1回の測定日・1か所の測定元。データは週次（食品営業許可）または固定版（Overture）で更新され、結果は変わりうる。
- 地点は主要駅中心で、住宅地・郊外の分布を代表しない。密集地ほど取りこぼしやすいことが示唆される（三宮）。
- 正解自体が上限200件で打ち切られており、「真に最寄りの店」ではなく「API が返す範囲での最寄り」に対する再現率である。
- 屋内や同じ建物内の店舗は座標が同じことがあり、座標だけでは利用者が実際にいた店を決められない（CheckInside: 座標だけの上位5件の正解率17%）。
- 送信先は「アクセス元の情報とリクエストの内容」を取得すると公表している（docs.openpoiapi.com/legal.html）。保存期間は公表されておらず、SLA もない。

## 採用した設計判断

1. 外部へ送るのは小数第3位に丸めた位置だけにする（`coarsen()`）。第2位は再現率が実用に耐えない。
2. 上限は200件、半径は固定の380m（300m＋升目の最大のずれ）とし、端末内で正確な位置からの距離で並べ直して上位8件を表示する（`rankCandidates()`）。並び順は API に任せない。同じ升目の中なら送信内容は完全に同じになる。
3. 名前と住所で重複をまとめ（近いほうの1件と、その出典だけを残す）、カテゴリ `unknown` と日本語名のないカテゴリは表示しない。
4. 取りこぼしと屋内の曖昧さに備え、名前で探す・手入力を常に同じ画面に置く。
5. 外部サービスの停止・変更に備え、外部 URL は `src/features/place/openPoi.ts` の1ファイルに限定し、応答は緩く検証する。手入力は外部に依存しない。
