# 脅威モデル

対象は画面（`src/`）、API サーバー（`server/`）、公開API契約（`contracts/family-hub.openapi.yaml`）、配信の設定（`deploy/`、`public/_headers`）。ここに書く「実装」は、コードと自動試験で確かめたという意味で、本番で安全と判定したという意味ではない。外部の侵入試験は行っていない。端末OS、外部の天気（Open-Meteo）、外部の場所検索（OpenPOI API）、運営者が設定する読み取りの補助の接続先の安全性は、この成果物だけでは保証しない。

## 資産・主体・境界

- 資産: 家族構成、予定、タスク、学校書類/OCR、支出、記録した場所、招待、セッション、監査記録、写真と動画、添付、パスワードの確認用の値、パスキーの公開鍵、確認コード（TOTP）の秘密、回復コード、鍵束（`FAMILY_HUB_KEYS`、または `FAMILY_HUB_SECRET`）、暗号化したバックアップとその鍵（`FAMILY_HUB_BACKUP_KEY`）、読み取りの補助の接続鍵。端末の正確な現在地と写真の位置情報も、既定では保存しない一時的な資産として扱う。
- 主体: 管理者／大人のメンバー／子どもメンバー／ゲスト、未認証者、招待受領者、運営者（`server/cli.ts` を実行できる人）、外部サービス。API内部値は `owner/adult/child/guest` を維持する。
- 信頼境界: ブラウザ↔API、API↔SQLite（本体の DB と監査の記録のファイル `audit.db`）、API↔メディアの保存先、API↔バックアップの置き場所（`FAMILY_HUB_BACKUP_DIR`）、API↔clamd、API↔SMTP、API↔読み取りの補助（LLM、同じ機械か家庭内だけ）、API↔利用者が指定したURLのページ、API↔Open-Meteo、家族グループA↔家族グループB、運営者の手元↔データベース、ブラウザ↔端末の位置情報、ブラウザ↔OpenPOI API（同意後だけ、Cookieなし）。

## STRIDE要約

状態の見方: 「実装」はサーバーで強制し自動試験がある。「実装（代役）」は外部の相手を代役に置き換えて試した。実物との接続は未確認で `evidence-pending`。

一覧・検索・詳細取得も、能力と対象の公開範囲をサーバーで毎回判定する。閲覧不可の個別対象は `NOT_FOUND` とし、存在の有無を漏らさない。フロント側の非表示は誤操作防止であって認可境界ではない。権限、招待、金融操作は直近の本人確認（既定5分、`FAMILY_HUB_RECENT_AUTH_MS`）がないと `403 REAUTH_REQUIRED` で拒否し、監査記録を残す。

年齢と役割: 誕生日は本人の申告で、確かめない。18歳未満（`ADULT_AGE`）の登録は保護者の同意の印（`guardianConsent`）がないと断るが、印は記録せず、保護者にも確かめない。18歳以上と申告した人にだけ `adult_declared_at` を残し、家族グループの作成と管理者への変更・移譲はこの人だけに許す（`ownerCandidateProblem`）。役割は招待のときと後の変更で管理者が選び、年齢からは決めない。子どもメンバーの上限には家計・場所・ヒント・読み取りの補助・家族の管理を入れない（`roleCeilings`）。16歳未満の法定代理人の同意（令和8年の改正）を扱う仕組みはなく、法務の確認は `evidence-pending`。

## セッションとCSRF

Cookie は `server/auth/sessions.ts` だけが発行する（`npm run audit:security` で検査）。https の配信では `__Host-fh_session` と `__Host-fh_pre`、loopback の http 開発では `fh_session` と `fh_pre` を使い、どれも `Path=/; HttpOnly; SameSite=Lax`、https では `Secure`。セッションの値は32バイトの乱数で、データベースには SHA-256 だけを保存する。有効期間は30日、無操作の時間切れ（既定30分、本人が変更できる）はサーバーで判定する。画面の残り時間の表示は案内にすぎない。パスワードの変更で本人のほかの端末を終了する。認証情報は localStorage/sessionStorage へ保存しない。

`NODE_ENV=production` では、https のオリジン、32文字以上の `FAMILY_HUB_SECRET` か鍵束の `FAMILY_HUB_KEYS`、clamd の設定がないと起動しない。開発用の既定の秘密は `NODE_ENV=production` では使われないが、配信物の文字列としては残る。

状態を変える要求は `Origin` と `Sec-Fetch-Site` を確かめ、セッション（サインイン前は `fh_pre`）に結んだ HMAC の `X-CSRF-Token` を要求する（有効な鍵で作り、引退していないすべての鍵で確かめる）。トークンは画面のメモリだけに置く。XSS対策の代替にはしない。出力エスケープ、依存管理、strict CSPを併用する。

パスワード変更の入力値と招待コードは Web Storage へ保存しない。招待コードはハッシュで保存し、作成時の応答でだけ返す。

## 確認コード（TOTP）と回復コード

- 検証はサーバーで行う（RFC 6238、SHA-1、30秒、6桁、前後1枠）。一度使った時間枠より前は受け付けず、同じコードを繰り返し使えない（`users.totp_last_step`）。
- 秘密は検証に元の値が要るのでハッシュにできない。鍵束の有効な鍵から HKDF で作った鍵の AES-256-GCM で、`v2.<kid>.<iv>.<tag>.<本文>`（AAD は用途と利用者 ID）として保存する。以前の形式は kid `legacy` で読む。鍵が漏れるとデータベースと合わせて秘密が読める。
- 鍵の入れ替えは `keys rotate` と `keys retire`（`deploy/README.md` の「鍵」）。鍵をなくしても起動し、その人の確認コードを「使えない」として扱う。回復コード（鍵に依存しない）かパスキーでサインインし、設定し直す。どれもないときは運営者が `totp reset --user` で消す（監査の記録に残る）。
- 回復コードは8個で、SHA-256 だけを保存し、1回ずつ使える。
- サインインの確認コードは1つの試行につき5回、設定の変更は15分に10回まで。
- 設定と解除には直近の本人確認が要る。

## 監査の記録（A6）

- **置き場所**: 別のファイル `audit.db`（`FAMILY_HUB_AUDIT_DB`、既定は本体の DB と同じディレクトリ、権限 0600。WAL と共有メモリのファイルも同じ権限になる）。**別のファイルにすること自体は守りを強めない**。API と同じ OS の利用者や root は、本体の DB と `audit.db` の両方を読み書きでき、trigger も外せる。分けたのは、記録の保持と確認を本体と独立に扱うため。
- **書き方**: 変更と同じトランザクションで本体の DB の `audit_outbox` に書く（id は UNIQUE）。確定の後（`Db.afterCommit`）、起動のとき、5秒ごとに、移送器が `audit.db` へ `INSERT OR IGNORE` で追記してから `audit_outbox` の行を消す。WAL では ATTACH した2つのファイルをまたぐトランザクションは全体として原子的にならないので、この順にした。2つの段の間で止まっても、次の回に同じ id を追記し直すだけで、重ならず欠けもしない（試験あり）。
- **鎖**: `hash = SHA-256(prev_hash ‖ 正規化した行)`。正規化した行は `[id, at, household_id, actor_user_id, action, target, detail]` の JSON。鍵は使わない（鍵を引退させても確かめられるように）。追記は `BEGIN IMMEDIATE` の中で末尾を読んでから行い、`INSERT` の trigger も「末尾の hash と次の番号を引き継ぐ行」しか受け付けないので、API と運営者の命令が同時に書いても鎖は分かれない（別の処理を3つと API を同時に動かす試験あり）。
- **trigger**: `audit_events` の UPDATE は常に、DELETE は checkpoint が覆う行以外を `RAISE(ABORT)` で断る。checkpoint は変えられず消せず、鎖にある行の hash と一致しないと書けない。trigger は書ける人には外せるので、守りの境界ではなく柵として扱う。
- **基準点**: 毎日、鎖の末尾（番号と hash）を運用ログ（`audit anchor day=… seq=… hash=…`）と本体の DB の `audit_anchors` に残す。バックアップの目録には、写した `audit.db` の鎖の末尾（`AuditLog.currentAnchor()` と同じ形）を入れ、確かめるときと復元のときに照らし合わせる。**改ざんに気づく仕組みの中心は、別の場所に残した基準点にある**。運用ログを別の機械へ送るか、基準点の行を別の場所へ控えておくこと。本体の DB の控えは、`audit.db` だけを古い写しに戻した場合などに気づくためのもので、両方を書き換えられる人には効かない。
- **確かめ方**: `audit verify [--anchors <運用ログから写したファイル>]` は、改変・削除・並べ替え・挿入・基準点より前の切り捨て、基準点と食い違う作り直し、prune を経ていない checkpoint を、見つけた行の番号とともに示す（終了コード2）。**最後の基準点より後の切り捨ては検出できない**（残った行はどれも正しくつながっているため）。起動のときと毎日、直近5000行を確かめ、食い違いは運用ログに出し、管理者の「変更の記録」の API に `chain.state = problem` として返す。`/ready` は落とさない（記録の食い違いで家族の利用を止めない）。
- **保持と prune**: 既定で24か月（`FAMILY_HUB_AUDIT_RETENTION_MONTHS`）。毎日の手入れか `audit prune [--before <日付>]` が、1つのトランザクションで (1) 消す区間の末尾の hash を `audit_checkpoints` に残し、(2) そのことを鎖に1行（`operator.auditPrune`）足し、(3) 区間を消す。DELETE の trigger は checkpoint が覆う行しか通さないので、行を消す道はこれだけになる。verify は checkpoint から続きを確かめ、最後の checkpoint を裏づける prune の行がなければ食い違いとする（頭を切るためだけに checkpoint を置く改ざんに気づく）。
- **記録しないもの**: 本文、秘密、トークン、確認コード、IP アドレス、端末の名前。`detail` は変えた項目の名前（`{"fields":["kind"]}`）だけ。IP を入れないのは、管理者が家族の記録を見られるので、家族の居場所や回線を管理者に明かさないため（端末の一覧は本人の「サインイン中の端末」でだけ見られる）。
- **読む人**: 家族の記録は `audit.read`（既定では管理者だけ。大人の上限に入れないので、個別の許可でも大人には渡せない。管理者に対する個別の拒否はできる）。見られない記録を指す行は ID を伏せる。アカウントの記録（サインイン、パスワード・メール・確認コードの変更、パスキー、ほかの端末のサインアウト）は本人だけ。
- 前の版で本体の DB にあった `audit_events` の行は、移行の7番目で `audit_outbox` へ同じ順に移し、鎖の起点にした（表は消した）。

## バックアップ（A8）

- **守るもの**: 置き場所（`FAMILY_HUB_BACKUP_DIR`）や持ち出した写しを手に入れた人に、記録・写真・添付を読ませない。どのファイルがあるかも、よく知られたファイルの hash から確かめさせない。
- **暗号**: `FAMILY_HUB_BACKUP_KEY`（32文字以上、鍵束とは別の値）から HKDF で用途ごとの鍵を導く。塊ごとに AES-256-GCM、AAD はファイルの ID・塊の番号・最後の塊か。ファイルと塊の名前は鍵つきの HMAC。目録も AES-256-GCM（AAD は世代の ID）で暗号化し、HMAC を付ける。置き場所に平文の hash や SQLite・JPEG の先頭のバイトが出ないことを試験で確かめる。
- **改ざん**: 1バイトの変更、塊の入れ替え・並べ替え・切り捨て、別の世代の目録の付け替えは、`backup verify` と復元で見つかる（終了コード2）。置き場所を消す・古い世代だけを残すことは防げない。別の場所へ持ち出すことで備える（deploy/README.md の 3-2-1）。
- **鍵**: バックアップの鍵を API の機械と置き場所の両方から離して保管すること。鍵と置き場所を同時に取られると読まれる。鍵をなくすと復元できない。
- **頻度と世代**: `FAMILY_HUB_BACKUP_DIR` と `FAMILY_HUB_BACKUP_KEY` があるときだけ、毎日（既定 03:00、`FAMILY_HUB_BACKUP_AT`）作り、作ったその場で確かめる。どちらかがなければ作らず、起動のときに運用ログへ出す。世代は日7・週4・月6（`src/domain/backupRetention.ts`）。命令は `backup now|list|verify <id>` と `restore <id> --to <dir>`（`deploy/README.md` の「バックアップ」）。
- **残る期間**: 退会したアカウントは最長6か月（月の世代の数）、削除した記録は完全に消すまでの30日を足して最長でおよそ30日と6か月、バックアップに残る。バックアップが止まっている間は古い世代も消えない。規約とポリシーに書いた。

## 運営者の命令（`server/cli.ts`）

利用期間の延長・利用の停止・メンバーの停止と再開、鍵の入れ替え（`keys status|rotate|retire`）、確認コードの消去（`totp reset --user`）は、データベースのある機械で実行する命令だけで行い、HTTP の経路を持たない。すべて監査の記録に `operator` として残す。監査の記録の確認・基準点・prune（`audit verify|anchor|prune`）もこの命令で行う。実行する人の本人確認は OS のアカウントに任せている。命令を実行できる人はデータベースも直接読み書きできるので、この層の悪用はこのアプリでは防げない。

## オフライン再送

予定・タスク・メモ本文の作成／更新だけを再送対象とし、削除、添付、家計、精算、招待、権限、認証、セッション、通知停止はキューへ入れない。再送待ちはIndexedDBへ最大50件・24時間だけ保存し、非抽出AES-GCM鍵、操作ごとのランダムIV、利用者・世帯・操作・schema versionを追加認証データにする。復帰時は自動送信せず、本人が内容を確認してから送る。別利用者への切替では消去し、セッション失効時は同じ利用者の再認証までロックする。

これは保存データの偶発的な読み出しへの多層防御であり、同一オリジンXSS、悪意ある実行コード、端末侵害から秘密を守る仕組みではない。再送前にはセッション、能力、権限リビジョン、対象版を再検証する。

## アップロードとメディア

対象はメモの添付と、アルバムの写真・動画。実装は `server/http/routes/media.ts` と `server/media/`。

1. 受け付ける形式はファイルの先頭から判定し、送られてきた名前や種類の申告は信じない（JPEG/PNG/PDF/MP4/MOV）。HEIC はこの配布の sharp で読めないので理由を示して拒否する。
2. 大きさの上限: 添付は PDF・画像10MB、動画120MB（サーバーの受け入れは130MiB）。アルバムは写真100MiB、動画4GiB、家族で20GiB、添付は家族で1GiB。
3. 受け取ったファイルは保存先の外の一時領域に置き、clamd の検査が `clean` のときだけ保存する。感染、接続不可、時間切れ、壊れた応答はすべて拒否する。本番は clamd の設定がないと起動しない。開発用の代役は検査をしないので、`NODE_ENV=production` では選ばれない。
4. 写真は sharp で読み直して位置情報を除き、動画は MP4/MOV の位置情報の箱を直接消す。解析できない動画は黙って保存せず拒否する。利用者が残すことを選んだ場合だけ残す。
5. SHA-256 はサーバーで計算し、同じ家族の重複を拒否する。
6. アルバムの大きなファイルは tus 1.0 の手順で8MiBずつ送る（経路は自前の実装）。同時に3件まで、未完了は24時間で消す。

配信:

- すべて `/v1/` の下だけで配る。`public/sw.js` は `/v1/` をキャッシュしない。
- 応答には `X-Content-Type-Options: nosniff` と `Content-Security-Policy: default-src 'none'; sandbox` を付ける。添付は、画面の中で開くリンクで種類が JPEG・PNG・MP4・PDF のときだけ `inline`、ほかは `Content-Disposition: attachment` で返す。
- 添付のリンクは5分で切れる署名付きで、さらにセッションが要る。署名は添付の ID・期限・表示方法（`inline` か `attachment`）に掛かる。種類と名前は配信のときに記録から読み、問い合わせの値は使わない。種類は許可した種類に限り、それ以外は `application/octet-stream` にする。
- 配信のたびに、閲覧者がその添付を今も見られるかを確かめる。権限や公開範囲が変わったり記録が消えたりすれば、期限の前でも開けない。

AVのclean判定は絶対安全を意味しない。未知脅威、パーサ脆弱性、誤検知に備え、最小権限と更新・監視を併用する。

未確認: 実物の clamd（EICAR を含む）とは接続していない。代役で OK・感染・無応答・壊れた応答・接続拒否を確かめた。sharp の解析器の脆弱性はこのアプリでは防げない。動画は再エンコードしないので、再生時の解析はブラウザに任せる。H.264 の再生とピクチャーインピクチャーは自動試験で確かめていない。

## 読み取りの補助（LLM）

既定では無効。`FAMILY_HUB_LLM_URL` と `FAMILY_HUB_LLM_MODEL` を設定したときだけ、OpenAI 互換の `/chat/completions` を呼ぶ。**接続先は同じ機械か家庭内だけで、家族の画像と本文を外部へは送らない**（本人の決定、2026-11-03）。

- 認める宛先: loopback、10/8・172.16/12・192.168/16、fc00::/7。`::ffff:` で表した IPv4 は IPv4 として判定する。0.0.0.0/8・100.64/10・169.254/16・fe80::/10・NAT64・6to4・グローバルは拒む（`server/adapters/destination.ts` の `isLocalAddress`）。
- 起動のとき: URL が読めない、資格情報を含む、IP をそのまま書いて範囲の外、のどれかなら起動しない（`loadConfig`）。名前を引いて範囲の外の答えが1つでもあれば起動しない（`prepareLlmClient`）。名前を引けないときは起動し、読み取りの補助を「使えない」とする（運営の記録に理由を出し、URL は書かない）。
- 要求のたび: 名前を引き直して全部の答えを確かめ、確かめた1つの宛先にだけ接続する。`http(s).request` に、名前を引き直さない `lookup`（`pinnedLookup`、URL の取得と共有する部品を許可側の判定で使う）と `agent: false` を渡す。途中で答えが公開の宛先に変わった名前には一度も接続しない。転送には従わない。応答は1MiBまで、誤りに URL と鍵を含めない。`npm run audit:security` が、`llm.ts` がこの形でだけ接続することを構文木で確かめる。
- 平文: loopback のほかへ平文の http で送るのは、`FAMILY_HUB_LLM_ALLOW_LAN_HTTP=1` を明示したときだけ。**このとき画像と本文と鍵は家庭内のネットワークを平文で流れる**。同じネットワークの機器から読めるので、できるだけ https を使う。
- 送るもの（家庭内の接続先へ）: 利用者が読み取りを選んだ画像（領収書・チラシ）を読み直して長辺1600pxの JPEG にしたものと、読み取りを選んだページのアドレスと本文（最大8000文字）。家族の記録は送らない。読み取る前に画面で説明する（`ReadingNotice`、文言は `src/content/ja.ts` の `reading`）。ページを読むときは、そのページを公開しているサイトから本文を受け取る（下の「URLの取得とSSRF」）。
- 家族ごとの同意: 外部へ送らないことに決めたので、家族ごとの同意の仕組みは作らない（[比較表](parity-matrix.md) の未決事項を閉じた）。運営者が有効にすると、`assistant.use` を持つ人（既定で管理者と大人のメンバー）が使える。
- 読み取る内容はデータとして渡し、ページの本文は JSON の値に入れる。指示の注入を完全に防ぐことはできないので、応答は信用しない。形を確かめ、提案として画面に出すだけで、自動では保存しない。
- 画像は検査を通してから読み、終わったら消す。
- 家族で同時に1件、1人1時間30回まで。既定の待ち時間は45秒（`FAMILY_HUB_LLM_TIMEOUT_MS`）。
- 接続鍵（`FAMILY_HUB_LLM_KEY`）は環境変数で渡す。

未確認: 実物の LLM には接続していない。代役（loopback）と、名前の答えを差し替える試験だけで確かめた（`server/test/llm.test.ts`）。家庭内の別の機械への実際の接続と、https の証明書の扱い（自己署名など）は確かめていない。

## URLの取得とSSRF

利用者が指定したURLのページをサーバーが取得するので、内部の宛先へ向けられる危険がある（`server/adapters/urlFetcher.ts`）。

- https の 443 番だけを許す。内部の名前（`localhost`、`.local`、`.internal` など）は名前を引く前に拒む。
- 名前を引いた結果のすべての宛先を確かめ、プライベート、ループバック、リンクローカル、メタデータ、文書用の範囲、IPv4 を埋め込んだ IPv6 を拒む。確かめた宛先に接続を固定し（`pinnedLookup`）、DNS の再束縛で差し替えられないようにする。
- 転送は3回までで、そのたびに同じ確認をやり直す。本文は2MiB、10秒で打ち切る。Cookie は送らない。
- 追跡用の引数を除いてから取得する。
- 試験用の緩めた設定は `server/main.ts` と `server/dev.ts` に書けないよう `npm run audit:security` で検査する。

未確認: 試験は http の代役で行っており、**実際の TLS ハンドシェイクを通る経路は確かめていない。** 取得先には運営者の機械の IP アドレスが見える。

## 外への接続の出口

サーバーからの外部接続は `server/adapters/` だけ（天気、SMTP、clamd、LLM、URLの取得）。`server/` が読み込めるのは `src/domain`、`src/authz`、`src/content` だけで、`npm run audit:security` と ESLint の `no-restricted-imports` で止める。`src/domain/commands` は `src/data/gateway.ts` の型を読むが、型だけで実行時の依存はない。データベースの SQL は文字列の連結を禁じ、`npm run audit:security` が構文木で確かめる。例外は `PRAGMA user_version` の1か所で、値は束縛できないが計算した整数だけが入る。

## 安定版でない部品とネイティブのモジュール

- データベースは `node:sqlite` を使う。**Node 24 では安定版ではない。** 利用は `server/db/db.ts` の1ファイルに閉じ、差し替えられるようにしている。Node の更新で動作が変わりうるので、更新のたびに全試験を流す必要がある。
- パスワードのハッシュは `@node-rs/argon2`（Rust の argon2 を使うネイティブのモジュール、MIT）を `server/auth/password.ts` だけで使う。Node の `crypto.argon2` は使わず、`npm run audit:security` が `server/` と `src/` のすべて（試験を含む）で禁じる。配備では `npm ci --omit=dev` で、その機械に合う組み立て済みの部品が入る。

## 鍵

- 鍵束（`server/auth/keyring.ts`）は `FAMILY_HUB_KEYS`（`kid=秘密` の並び）と `FAMILY_HUB_ACTIVE_KID`。`FAMILY_HUB_KEYS` がなければ `FAMILY_HUB_SECRET` を kid `legacy` の有効な鍵とする。鍵には kid を付け、用途ごとの鍵を HKDF で導く。CSRF・パスワードの再設定・添付のリンクは有効な鍵で署名し、引退していないすべての鍵で確かめる。確認コードの秘密は `v2.<kid>.<iv>.<tag>.<本文>`（AES-256-GCM、AAD は用途と利用者 ID）で保存する。
- 起動のたびに kid ごとの指紋を `key_fingerprints` と照らし合わせる。鍵のない暗号文や、指紋の違う kid があっても起動し、運用ログに理由を出す。その人の確認コードは「使えない」として扱い、回復コード（鍵に依存しないハッシュ）とパスキーでサインインでき、設定から登録し直せる。要求が 500 になることはない。
- 未確認: 鍵束は API と同じ機械の環境変数に置く。機械を取られたときの保護（HSM や外部の鍵管理）はない。

## 位置情報と外部送信

- 正確な位置（端末・写真）は場所の選択中だけ画面の内部に保持し、保存・送信・再送キュー・ログへ出さない。型（`CoarseCenter`）と厳格なスキーマ（`placeRefSchema` は未知の項目を拒否）で構造的に防ぐ。
- 外部へ送るのは、小数第3位（約110m×90m）に丸めた位置と固定の半径（380m）、または確定した検索語だけ。半径を正確な位置から計算すると升目の中の位置が逆算できるため、丸めた中心だけで決まる値にする（同じ升目の中なら送信内容は完全に同じ）。`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`、`cache: 'no-store'` とし、Service Workerでもキャッシュしない。実測では固定半径で丸めても上位10件の再現率は平均0.961（`docs/audits/place-lookup-probe.md`）。
- 現在地は利用者の操作ごとに一度だけ取得し、継続追跡しない。誤差が1000mを超える位置では近くの候補を出さない。
- 保存するのは選んだ場所の名前・住所・場所の座標（小数第5位）・出典・取得方法だけ。`place.read` を持つ管理者と大人のメンバーだけに返し、子ども・ゲストには項目ごと除く。読めない人は書けない。
- 残るリスク: OpenPOIにはIPアドレス、丸めた位置、時刻、ブラウザの種類、送信元のオリジンが届き、複数回の検索を結び付けられうる。送信先は取得した情報の保存期間を公表しておらず、SLAもない。サービスの変更や規約の変更時は `PLACE_LOOKUP_NOTICE_VERSION` を更新して同意を取り直す。本番では中継APIを置けばIPアドレスを隠せるが、送信先の変更として公表内容の改訂が必要になる。
- 法令との対応（法的助言ではない）: アカウントに結び付いた位置情報は個人情報として扱う（個人情報保護委員会ガイドライン）。外部送信は電気通信事業法の外部送信規律の対象となりうるため、送信先・送る内容・目的を `/settings/location` で公表し、初回利用前に同意を求める。適用の可否と文言は専門家の確認を要する。
- 支出の場所もメモの場所も、編集で外せる（`updateExpense`、`updateMemo`）。

## 認可の境界の点検（2026-10-03）

- `/settings` を直接開くと家族タブへ落ちる経路があり、子ども・ゲストに家族の管理画面が表示されていた。タブごとの能力表で経路とタブ表示を判定し、`/settings` は許可された最初のタブへ置き換える。
- ヒントは固定のデータを画面へ直接読み込んでおり、能力の確認がなかった。`insights.list()`（`GET /v1/insights`）を通し、`insight.read` を確認したうえで、閲覧者に見えている記録だけから導く。
- 通知（`notification.manage`）と関連リンク（`resource.read`）は、画面でも能力で出し分ける。mock では通知設定にも能力の確認を加えた。
- 招待コードは作成時の応答でだけ返し、一覧では返さない。招待の受け付けは、存在しない・期限切れ・使用済み・取り消しを区別しない。
- パスキーのサインインは、開始・端末での本人確認・検証の3段階が終わってから先へ進む（以前は開始だけで進んでいた）。検証はサーバーで行う。
- 繰り返しの「この予定だけ」が無視され、シリーズ全体が消える不具合を直した。範囲は例外日またはシリーズの分割で表し、削除・分割の前の状態を保存して7日以内に戻せる。

## 配備ヘッダー

`public/_headers`と`deploy/nginx.conf`はstrict CSP、HSTS、`frame-ancestors 'none'`、`base-uri 'none'`、`form-action 'self'`、nosniff、COOP、CORPを同じ値で含み、`npm run audit:security` が一致を検査する。`connect-src` は `'self' https://api.openpoiapi.com`、`media-src` は `'self' blob:` だけで、完全一致を検査する。`Permissions-Policy` は `geolocation=(self)` で自サイト以外の位置情報利用を禁じる。`location /v1/` の転送先も検査し、この中で `add_header` を書くと見出しが消えるので禁止している。実スタックの E2E は同じ見出しを `vite preview` で付けて流す（localhost の http で動かすため、HSTS と `upgrade-insecure-requests` だけ外す）。nginx そのものの動作、TLS証明書、HSTS preload、reporting endpointは配備先で検証する。

API は `trustProxy: 'loopback'` で、同じ機械の nginx から届く `X-Forwarded-For` の末尾だけを信じる。別の機械の転送を挟む場合は、この設定を変えないと回数制限が転送元の1つの宛先に集まる。

## 依存関係

依存はすべて固定の版で `package-lock.json` に記録する。これは将来の脆弱性不存在を保証しないため、lockfileを含む継続監査とlocalhost限定の開発サーバー運用を維持する。結果は `docs/audits/verification-report.md` に残す。
