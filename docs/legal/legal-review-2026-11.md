## 0. 前提と確認の方法

- **運営の形（運営者が決めたもの）**: 事業者（名前は未記入）が、ほかの家族に**有料**で提供する。登録から14日間は試用で、その後は運営者が手作業で利用期間を延ばす。アプリの中に支払いや購入の流れは**ない**。登録には名前・メール・パスワード・誕生日が要る。1家族8人まで。18歳未満の子どもメンバーがいることもある。管理者は24か月分の変更の記録を見られる。
- **確認したアプリの事実**（リポジトリを読んで確かめたもの。2026-11-06 時点）
  - 規約とポリシーの本文は `src/content/legal.ts`。サインインしていなくても `/settings/legal` で読める。
  - 登録画面は「草案（新しいタブ）を確認してください」というリンクを出すだけだった（2026-11-07 に直した）。**同意のチェック欄も、同意した版と日時の記録もない**。18歳未満なら「保護者の同意を得ています」のチェックがないと登録できない。ただし、このチェックは記録しない。
  - 外部への送信
    - **OpenPOI**（場所検索）: 利用者が同意したあと、**ブラウザから直接**、約100m単位に丸めた位置か検索語を送る。CSP の `connect-src` で許しているのはここだけ。同意した版と日時は記録する。子どもメンバーとゲストはこの機能を使えない。提供元の公開文書には、運営者の名称・所在国・サーバーの国が書かれていない。
    - **Open-Meteo**（天気）: **サーバーから**、運営者が決めた固定の地点だけを送る。利用者の情報は送らない。提供元の規約では、無料の API は**商用以外に限る**。
    - **メール**: 送るのはパスワードの再設定と、メールアドレスを変えたときの知らせの2種類だけ。広告のメールは送らない。
    - **読み取りの補助（LLM）**: 同じ機械か家庭内のネットワークで動かす。外部へは送らない。
    - **ホスティング**: 運営者が自分で置く（`deploy/README.md`）。nginx の設定例はアクセスログを止めていないので、IPアドレスはサーバーのログに残りうる。
  - 利用期間が切れると、画面には「運営者へ利用の延長を依頼してください」と出て、**サインアウトしかできない**。記録の書き出しも、アカウントの削除もできない。
  - アプリの中の通知は、タスクの期限と予定の出発の**お知らせだけ**。メンバーどうしでメッセージを送る機能はない。ただし、予定・メモ・アルバムは公開範囲で「選択したメンバー」を選べる。
- **出典の取り方**
  - 法令は e-Gov 法令検索の API（v2）で、2026-11-06 時点の現行の版を取り、条文を確かめた。施行前の改正は、改正履歴にある「未施行」の版で確かめた。
  - **個人情報保護委員会のウェブサイトは、2026-11-06 に「緊急メンテナンス」で止まっていた。** 改正法の案内ページだけは Web アーカイブ（2026-11-05 取得）で読めた。ガイドラインと Q&A の原文は読み直せていない。下の表では「（原文は未確認）」としている。
  - 消費者庁の逐条解説（消費者契約法8条）と、総務省の電気通信事業参入マニュアル［追補版］（令和5年1月30日改定）は、PDF の本文を読んだ。
- **根拠の強さ**: N は法律・政令・規則、O は官庁のガイドライン・Q&A・逐条解説・マニュアル。
- **確かさ**: 高・中・低は、条文や官庁の資料がこのアプリにどれだけはっきり当てはまるかの見立て。

## 1. 要点（重い順）

1. **免責の条項は、たぶん無効になる**（消費者契約法8条1項1号・3号）。消費者庁の逐条解説は、「事業者に責に帰すべき事由があっても一切責任を負わない」を1号で無効になる例に挙げている。→ 直した。
2. **公表しなければならない事項が足りない**（個人情報保護法32条、施行令10条）。→ 直した（【】の欄は運営者が記入）。
3. **規約が契約の内容になる手当てが弱い**（民法548条の2）。規約の変更の条項に、効力が生じる時期と周知のしかた（548条の4）がない。→ 表示と変更の条項は直した。同意の記録は残る。
4. **有料にするなら「特定商取引法に基づく表記」が要る**（特商法2条2項・11条、施行規則2条・23条）。ウェブやメールで申込みを受ける以上は「通信販売」に当たる。申込みの画面を作るなら、12条の6の「最終確認画面」の義務もかかる。→ 表記の草案を作った。
5. **16歳未満についての改正は、公布済みで、まだ施行されていない**。令和8年法律第56号が令和8年7月17日に公布された。新しい40条の2と35条9項は、e-Gov では「公布の日から起算して二年を超えない範囲内において政令で定める日」に施行とされ、施行予定日は最も遅くて 2028-07-16。施行日を決める政令は確認できなかった。条文の中身は「本人」を「法定代理人」と読み替える規定と、16歳未満の本人が利用の停止を求められる権利である。→ 説明を直した。**保護者の同意を記録する仕組み**を施行前に作る（附則5条で、施行前の同意も使える）。
6. **電気通信事業の届出が要るかは、はっきりしない**（確かさ：低）。総務省のマニュアルでは、ファイル共有やオンラインストレージは届出が要らない（第三号事業）。一方で「宛先として指定された閲覧者」へ見せるもの（グリーティングカードの例）や、保存したことを知らせるメッセージ機能は「他人の通信の媒介」に当たり、届出が要る。「選択したメンバー」に見せるメモや予定がどちらに当たるかは、**総務省（総合通信局）に事前に相談**する。どちらであっても、通信の秘密（4条）は守る必要がある（164条3項）。
7. **利用期間が切れたあとに、自分の記録へ手が届かない**。消費者契約法10条、民法548条の2第2項（不当な条項）、個人情報保護法22条・33条・35条とぶつかりうる。→ 規約で手当てしたが、画面から書き出しと削除をできるようにするのが残る。
8. **外部サービスの規約**（法令ではない）。Open-Meteo の無料 API は商用以外に限られる。

## 10. 運営者が決めること

1. 運営者の名称、法人か個人か、住所、代表者（または責任者）、電話番号、メールアドレス。
2. 問い合わせ・苦情・開示などの請求・合理的配慮の申出の窓口（電話のほかに文字で連絡できる方法）。
3. 料金（家族グループごとか人数ごとか、月額か年額か、税込の額）。
4. 支払の時期と方法、入金を確かめてから延長するまでの日数。
5. 契約者はだれか（18歳以上の管理者に限るか）。管理者を渡したときに契約者も替わるか。
6. 更新のしかた（自動か手か）。自動なら、知らせる時期と解約の締め切り。
7. 解約の方法、受け付ける時期、返金（日割りか）、解約料の有無（消費者契約法9条）。
8. 利用期間が終わったあとのデータ（書き出しと削除ができる期間、消すまでの期間、事前の知らせ）。
9. 軽過失のときの責任の上限額（規約の【金額】）。
10. 規約を変えるときの予告期間。
11. サーバー、バックアップの置き場所、SMTP 事業者と、その国。外国なら28条への対応。
12. 本番のデータに触れてよい人と手順、漏えいしたときの責任者と連絡の流れ（26条）。
13. 16歳未満の保護者の同意をどう確かめて記録するか（施行前に作る。附則5条）。
14. 管理者が操作の記録を見ることを、どう説明し、どう同意を得るか。
15. 電気通信事業の届出について総務省に相談するか。結果が出るまでメッセージやお知らせの機能を足さないか。
16. Open-Meteo の有料の契約か、天気の取得元の変更か。
17. 試用の終わりや有料の案内をメールで送るか（送るなら同意を取る）。
18. アクセスログを残す期間。

## 11. 公開の前に弁護士に見てもらうこと

1. 「運営者の責任」の条項と上限額の決め方、試用中の0円の利用者の扱い（消費者契約法8条・10条）。
2. 利用期間が終わったあとに閲覧・編集を止めること、データを残す期間と消すこと（消費者契約法10条、民法548条の2第2項）。
3. 規約の変更、サービスの変更と終了の条項（民法548条の4、消費者契約法10条）。
4. 登録と招待の流れで規約に同意してもらう形と、同意の記録（民法548条の2）。
5. 家族の中での表示と、管理者が操作の記録を見ることが27条の「第三者提供」に当たるか。他人の情報や要配慮個人情報を保存することの整理（20条2項）。
6. 16歳未満の改正（令和8年法律第56号）への対応。政令・規則・ガイドラインが出たあとの見直し。
7. 電気通信事業の届出の要否（総合通信局への相談とあわせて）、外部送信規律、通信の秘密と内容を見る場合の同意。
8. 外国の事業者を使う場合の28条の扱いと公表のしかた。
9. 特定商取引法に基づく表記の内容、最終確認画面、住所と電話番号を省くかどうか。
10. 32条の公表事項（安全管理措置の書き方）と、開示などの請求の手続。
11. 未成年者の登録（民法5条・21条）と、子どもと保護者の同意の記録。
