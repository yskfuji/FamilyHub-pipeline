# アクセス制御マトリクス

状態: サーバーで強制する（`src/authz/policy.ts`、`src/domain/commands`、`server/http/app.ts`）。同じ規則をモックも使う。役割の既定は `roleCeilings`、個別の許可と拒否は `permissionOverrides`。外部の侵入試験は行っていない。

利用期間が終わった家族グループでは、規則で判定する操作をすべて `403` で拒否する（記録は残る）。

直近の本人確認（`recentAuth`）が要る操作: 家族グループの名前の変更、役割と個別権限の変更、招待の作成と取り消し、管理者の移譲、退出、メンバーの停止と削除、精算と取り消し、支出の編集・削除・復元、メールアドレスの変更、確認コードの設定と解除、アカウントの削除。

## 判定規則

1. セッションからサーバーが閲覧者を特定する。クライアントのrole値は信頼しない。
2. 利用停止・不明な所属は既定拒否とする。
3. 役割の既定権限へ個別上書きを適用する。明示的な拒否を優先し、許可は役割上限を越えない。
4. リソース能力と公開範囲の両方を満たした場合だけ返す。閲覧不能な個別リソースは `NOT_FOUND` として存在を漏らさない。
5. 最後の管理者の降格・削除を拒否する。権限、招待、金融操作は監査イベントを残す。
6. 項目単位の秘匿: 記録した場所は `place.read` を持つ閲覧者にだけ返し、持たない閲覧者には項目ごと除いたメモ・支出を返す。子どもとゲストの役割上限には含めず、個別許可でも付与できない。読めない項目は書けない（`place.read` なしで場所を書き込むと `FORBIDDEN`）。

7. 設定のタブは、タブごとの能力でだけ開ける。`/settings` は許可された最初のタブへ置き換え、知らないタブは404とする（家族タブへ黙って落とさない）。
8. 招待コードは作成時の応答でだけ返し、一覧では返さない。
9. 家族グループの上限は8人。管理者は18歳以上と確認できた人にだけ渡せる。
10. 確認コードの秘密、回復コード、パスワードの確認用の値は、本人にも返さない。

UIの非表示は操作補助であり安全境界ではない。サーバー、mock gateway、OpenAPIは同じ制約を要求する。経路ごとに認証・権限・CSRF・冪等の宣言が必須で、宣言のない経路は起動時に止まる（`server/http/app.ts`）。`npm run audit:routes` が経路と契約を照合する。
