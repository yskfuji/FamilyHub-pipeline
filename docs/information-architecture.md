# 情報設計とタスク設計

## 目的

「記録する」より先に「今日どう動くか」を支援する。入口をドメイン別のカード一覧にはせず、Todayを判断順に構成する。

```text
公開
├── /welcome
├── /auth
└── /onboarding

世帯内
├── /today                 要確認 → 時間軸 → 自分の担当 → 未精算 → 天気影響
├── /calendar/:eventId?    月・週・一覧（繰り返しは表示範囲で展開）→ 予定詳細（?on=日付 でどの回か）→ この予定/これ以降/すべて
├── /tasks/:todoId?        担当/確認フィルタ → 状態遷移（繰り返しは完了で次の回へ）→ 今回だけ/すべて
├── /notes/:memoId?        本文 → 共有範囲 → 場所 → 添付検査状態 → OCR/原本照合
├── /budget/:expenseId?    月次（計算値）→ 費目 → 相手別残高（相殺済み）→ 支出 → 支出詳細（場所・負担・精算の履歴）→ 精算の履歴
├── /places/:placeKey?     記録した場所（最近使った順が既定）→ その場所の支出・メモ。管理者と大人だけ
├── /insights              記録から導いたヒント → 根拠 → 任意の次操作
├── /settings/*            家族/サインインとセキュリティ/共有とプライバシー/通知/位置情報/表示・操作/関連リンク（能力のあるタブだけ。/settings は最初の許可タブへ）
└── /showcase              内部監査buildだけの画面・テーマ・異常状態
```

## 主なタスク

| ユースケース | 最短経路 | 失敗・復旧 |
|---|---|---|
| 今日の確認事項を終える | 今日 → 要確認 → タスク詳細 → 完了 | 競合時は上書きせず、差分確認を促す |
| 繰り返し予定を変更/削除 | 予定 → 月/週/一覧 → 予定詳細 → 編集範囲選択 | この予定/これ以降/すべてを明示し、既定はこの予定だけ。削除は確認画面 |
| 紙のお知らせを共有 | Notes → 添付 → 隔離 → clean後に閲覧 | 拒否理由、許可形式、再選択を表示 |
| 立替を精算 | 家計 → 支出行 → 支出詳細 → 「○○さんの残りを精算」 | 二重精算は競合として拒否。取り消しは支出詳細と家計の「精算の履歴」から、記録を残したまま行う |
| 支出を直す・消す | 家計 → 支出詳細 → 内容を編集／支出を削除 | 精算の記録がある間は金額・負担の変更と削除を止め、先に取り消すよう案内。削除は7日以内なら元に戻す |
| 記録した場所を振り返る | その他（モバイル）または左レール → 場所 → 場所の詳細 → 支出・メモ | 場所がなければ付け方を案内。子ども・ゲストは開けない |
| 支出・メモに場所を付ける | すぐに追加（支出）またはメモ作成・編集 → 場所を追加 → 現在地／写真から／名前で探す／手入力 → 候補を選ぶ | 初回は外部送信の説明と同意。拒否・精度不足・写真に位置なし・外部停止は理由を示し、名前検索・手入力へ。子ども・ゲストには表示しない |
| 情報を横断検索 | グローバル検索 → 結果 → 詳細URL | 一致なしを静かな空状態で示す |
| 家族の権限/招待を管理 | 設定 → 世帯 → メンバー権限/招待作成 | 唯一の管理者の降格を拒否。招待は24時間・1回でコードを作成直後だけ表示 |
| 認証とセッションを管理 | 設定 → セキュリティ → パスキー/パスワード/端末 | デモ登録を明示。パスワード入力は閉じると破棄。対象端末だけ確認後に終了 |
| 通知を調整 | ベル/Settings → 通知 → 延期/停止/設定 | 現在時刻と状態を表示し、30分延期と停止を常に明示。設定で出し分け、夜間は7:00にまとめる |
| 共有と通知の表示を変える | 設定 → 共有とプライバシー | 新しく作るものの共有範囲の初期値と、通知の題名・内容の表示を本人が変える。ほかの設定は上書きしない |

## レスポンシブ原則

- 760px超: 左レール、本文、必要時の右詳細ペイン。
- 760px以下: 今日/予定/タスク/メモ/その他の5項目ボトムナビ（家計・場所・ヒント・設定は「その他」）。「その他」はモーダルで、Escape で閉じ、表示中の画面が中にあるときは「その他（表示中：…）」と示す。詳細は全幅。
- デジタル庁デザインシステムは画面下部の固定ナビを非推奨としている（反証、E25）。一方で隠したナビは見つけにくい（E24）ため、ボトムナビを残しつつ、端末下部の安全領域に対応し、詳細画面の場所表示などからの文脈の入口を併設する。
- コンテナの幅に応じてカードを縮退。長い日本語は `overflow-wrap` とGridの `minmax(0,1fr)` で処理し、水平オーバーフローを隠さない。
- アイコン単独操作には必ずアクセス可能名を付ける。主要な意味は本文ラベルも併記する。
