# 実機での確認（2026年11月）

自動の試験（Playwright の Chromium と WebKit、iPhone のシミュレーター）では確かめられないことを、手元の端末で確かめる手順と結果。

## 何で動かすか

- **画面:** 見本の家族が入った内部監査用のビルド（`npm run build:audit` → `dist-audit`）。サーバーは使わず、データは端末の中だけで動く（見本のデータだけで、実データは入らない）。
- **配信:** 開発用の Mac から、家庭内の LAN に一時的に配信する。

  ```sh
  npx vite preview --outDir dist-audit --host <Mac の LAN のアドレス> --port 4320 --strictPort
  ```

  確認が終わったら止める。アドレスと QR はリポジトリに書かず、その場で渡す。
- **実サーバーにつなぐ確認は、この手順に含めない。** 実サーバーは loopback 以外への平文の http を断る（`server/config.ts`）。LAN で使うには https の証明書が要る（mkcert などで作り、端末に信頼させる）。サインイン・アップロード・二段階認証など、実サーバーに関わる流れは `npm run test:real` で確かめた範囲として扱う。
- **状態を切り替える:** 内部監査用のビルドでは、URL に `?scenario=` を付けて状態を変えられる（`empty`・`offline`・`conflict` など。`src/app/AppContext.tsx`）。

## 確かめること

結果の欄には、○（問題なし）・×（問題あり）・—（確かめていない）を書く。×のときは、どの画面で何をしたら何が起きたかを、下の「気づいたこと」に書く。写真があれば添える。

| # | 確かめること | 手順 | 端末1 | 端末2 | 端末3 |
|---|---|---|---|---|---|
| D1 | 最初の表示 | 履歴とキャッシュを消してから `/today` を開く。真っ白な時間が長くないか。すぐに「読み込んでいます。」と印が出るか | | | |

## iPhone のシミュレーターでの確認（実機の代わり）

Xcode の iPhone シミュレーター（iPhone 17、402×874pt）の Safari で、同じビルドを開いて撮った（2026-11-07）。実機ではないので、指で触ったときの感じ、VoiceOver、写真の選択、ホーム画面への追加、日本語の入力は確かめられない。

| 確かめたこと | 結果 | 対応 |
|---|---|---|
| 今日・予定・タスク・メモ・家計・アルバム・規約を昼の表示で開く | 表示は崩れない。ただし今日の画面の「確認待ちのタスクがあります」の欄で、ボタンが横に並び、文の列が数文字の幅に押しつぶされた | 知らせの欄のボタンを文の下に置く規則を、390px 以下から、下のナビが出る幅（`width < 42.7rem`）に広げた（`src/design-system/global.css`）。撮り直して直ったことを確かめた |
| 端末を夜の表示にして開く | アプリは昼の色のままだった。「端末に合わせる」を選んだときだけ従い、まだ選んでいない最初の状態は昼に決めていた | まだ選んでいないときは端末の昼と夜に従うようにした（`src/app/devicePreferences.ts`）。撮り直して、今日と家計が夜の色になることを確かめた |
| 文字の大きさを最大（アクセシビリティの XXXL）にする | Safari の帯は大きくなるが、ページの文字は変わらない。Safari のウェブページは、端末の文字の大きさの設定に従わない（ページの拡大で大きくする） | 変えていない。ページの拡大（200%）と文字の間隔は、自動の試験（LAYOUT-3 など）で確かめている。実機で Safari の「ページの拡大」を確かめる（D13） |
| 下のナビ、すぐに追加のボタン、上部 | ノッチと下端の帯に隠れない。すぐに追加のボタンは、スクロールの途中で本文の上に重なるが、ページの最後には余白がある（設計どおり） | — |
