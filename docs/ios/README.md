# iOS アプリ（iPhone と iPad）

iPhone と iPad では、Web アプリの代わりに SwiftUI で作ったアプリを使う。Web アプリは机と Android のために残す。
作り方の段階（S0〜S8）と決めたことは、この文書の終わりの「段階」にまとめる。

## 置き場所

| 場所 | 中身 |
|---|---|
| `ios/project.yml` | xcodegen の定義。`FamilyHub.xcodeproj` はここから作り、リポジトリに入れない |
| `ios/Config/Base.xcconfig` | 全体の設定（iOS 26、Swift 6、iPhone と iPad） |
| `ios/Config/Local.xcconfig` | この Mac だけの設定（チーム ID、バンドルの接頭辞、端末の ID）。リポジトリに入れない。`Local.xcconfig.example` を写して作る |
| `ios/App/` | アプリの入口とアイコン |
| `ios/Packages/FamilyHubKit/` | アプリの中身（Swift Package） |

`FamilyHubKit` の target:

| target | 中身 | 元にした Web のファイル |
|---|---|---|
| `FHModel` | 型（Codable） | `src/domain/types.ts` ほか |
| `FHCopy` | 文言（生成） | `src/content/*.ts` |
| `FHDomain` | 計算（日付・祝日・書式など） | `src/domain/*` |
| `FHGateway` | サーバーと見本の窓口 | `src/data/gateway.ts`、`src/data/mockGateway.ts` |
| `FHDesign` | テーマ・ブランドの印・部品 | `src/design-system/*` |
| `FHFeatures` | 画面 | `src/features/*`、`src/app/*` |

外部の Swift のライブラリは使わない。

### 円の記号
Apple の ICU（JavaScriptCore と Foundation）は円の記号を半角の `¥` で書く。サーバー（node）と Web（Chrome）は全角の `￥` で書く。アプリでは全角にそろえる。

- Swift の `Format.yen` は自分で組み立てる。
- 見本の仕組みは `src/native/nativePolyfills.ts` で置き換える。

## 見本のモード

アプリには見本の家族（森さんち、碧さん＝管理者）が入っていて、サーバーなしで全部の画面を動かせる。

- 変更は記憶の中だけに残る。アプリを閉じると元に戻る。
- 見本の時計は Web と同じく、2026年9月30日 7:45 から始まる。

## サーバーにつなぐ

サーバーは cookie で認証する（`__Host-fh_session`）。通信は `FHGateway` の `APIClient` と `HTTPGateway`（Web の `src/data/httpGateway.ts` の写し）。

- cookie は URLSession の入れ物に任せる。Bearer のトークンはない。
- 変更の要求には、CSRF の token（`GET /v1/auth/csrf`）・`Idempotency-Key`・分かっていれば `If-Permission-Revision` を付ける。403 CSRF なら token を取り直し、同じ冪等キーで1回だけ送り直す。
- サインインのたびにサーバーは token を結び直すので、アプリも覚えた token を捨てる。
- Origin は付けない。サーバーは Origin がない要求を通す（`server/http/app.ts`）。
- User-Agent は `Yoridokoro/<版> (iPhone; iOS x) FamilyHubApp/<版>`。サーバーは、サインイン中の端末の一覧に「iPhone アプリ」「iPad アプリ」と出す（`server/auth/deviceLabel.ts`）。名前を出すだけで、期限や権限は変えない。
- 平文の http は、同じ Mac（127.0.0.1・localhost）のシミュレーターだけで使う（Debug の `App/Info-Debug.plist` と `APIClient.allows`）。
- パスキーは、登録できるドメインと apple-app-site-association の配信が要るので、本物のドメインができるまで画面に出さない。

### シミュレーターから（127.0.0.1）

```sh
npm run dev:server        # API を 127.0.0.1:8799 で動かす（見本の家族。aoi@example.test）
# アプリを FH_DEV_SERVER_URL=http://127.0.0.1:8799 で作り、サーバーにつなぐ UI の試験を流す
TEST_RUNNER_FH_LIVE=1 xcodebuild -project ios/FamilyHub.xcodeproj -scheme FamilyHub \
  -destination 'platform=iOS Simulator,name=iPhone 17' FH_DEV_SERVER_URL=http://127.0.0.1:8799 \
  test -only-testing:FamilyHubUITests/FamilyHubUITests/testLiveServerSignInAndOut
```

### 失敗の場面を起こして確かめる（`npm run verify:ios:live`）

`scripts/ios/live.mjs` が、使い捨てのデータベースで開発用のサーバー（127.0.0.1:8799）を動かし、その前に切り替えのできる中継（127.0.0.1:8798）を置いて、`LiveServerUITests` と `testLiveServerSignInAndOut` を iPhone のシミュレーターで流す。試験の側からも同じサーバーを別の端末として呼び、次を確かめる。

- 通信が切れている間に追加したタスクが未送信の変更として残り、戻ってから送ると1件だけ届く（中継の `/__proxy/offline`・`/__proxy/online`）。
- ほかの端末で先に変えたタスクを保存すると、版の競合を知らせる。
- 本人確認の時間（この確認では20秒。`FAMILY_HUB_RECENT_AUTH_MS`）を過ぎてから招待を作ると、パスワードを聞いてから同じ操作を続ける。
- 管理者がメンバーの権限を変えると、読み直したときに見られない画面が消える。
- 無操作の時間（1分）の前に予告し、過ぎるとサインインの画面に戻る。

ビルドは `ios/build/live` に分けて置く（接続先の値が違うため）。iPad のタブの帯は後ろの項目を隠すので、この確認は iPhone で流す。

### 実機から（同じ Wi-Fi、https）

1. mkcert を入れる（一度だけ）: `brew install mkcert`、`mkcert -install`（Mac にルート証明書を入れる）。
2. `open "$(mkcert -CAROOT)"` で `rootCA.pem` を iPhone に送り、「設定」→「一般」→「VPNとデバイス管理」で入れ、「一般」→「情報」→「証明書信頼設定」で信頼する（一度だけ）。
3. `npm run dev:lan` を流す。API は 127.0.0.1 のまま、Vite だけが https で LAN に出て `/v1` を中継する。証明書は `.certs/` に作る（リポジトリに入れない）。8787・8000・4310 は使わない。
4. 表示された URL を `ios/Config/Local.xcconfig` の `FH_DEV_SERVER_URL` に書く。xcconfig では `//` が注釈になるので、`https:/$()/<Mac の名前>.local:4330` のように書く（表示のとおりに写せばよい）。
5. `npm run ios:device` で入れ、はじめの画面で「サーバーにつなぐ」を選ぶ。初回は「ローカルネットワーク」の許可を聞かれる。

## 確かめ方

```sh
npm run ios:export     # 生成物を作り直す（Web の側を変えたとき）
npm run verify:ios     # 生成物が最新か → xcodegen → swift test → シミュレーター向けのビルド
```

- `swift test --package-path ios/Packages/FamilyHubKit` だけなら数秒で終わる（macOS で動く）。
- `verify:ios` は、iPhone 17 と iPad Pro 11-inch のシミュレーターで UI の試験（`ios/UITests`）を流す。見本のモード（`-FHSampleMode`）で、各画面の主な使い方を動かし、昼と夜（一部は文字を最大にして）`performAccessibilityAudit()` にかける。
  - 監査で除くものは `ios/UITests/Audit.swift` に理由とともに書いてある: ガラスのタブの帯と上部（と、上に留めた帯）に重なった要素の濃さ、画面の端で一部だけ見えている要素の濃さ、要素を特定できない文字の大きさと「切れている」の指摘、括弧や中黒を含む文の「切れている」の指摘（日本語の詰め組みを見込まないため）。
  - 指摘があれば3秒待ってもう一度測り、2回とも出た指摘だけを失敗にする（読み込みや切り替えの途中で薄く見えた要素を、回ごとに違う形で指摘したため。本当に足りないものは2回とも出る）。
- `verify:ios` は `npm run verify` の最後に入っている。macOS と Xcode がない所では飛ばす（`FAMILY_HUB_SKIP_IOS=1` でも飛ばせる）。

## 実機に入れる

1. Xcode の Settings → Apple Accounts に、開発者のチームの Apple ID を足す（一度だけ）。
2. iPhone で「設定」→「プライバシーとセキュリティ」→「デベロッパモード」を入れ、Mac を信頼する（一度だけ）。
3. `ios/Config/Local.xcconfig.example` を `ios/Config/Local.xcconfig` に写し、次の値を入れる。
   - `FH_TEAM_ID`（チームの ID。証明書の名前の括弧の中の ID ではない。`Local.xcconfig.example` に調べ方がある）
   - `FH_BUNDLE_PREFIX`（世界で1つの名前）
   - `FH_DEVICE_ID`（`xcrun devicectl list devices` で分かる）
4. `npm run ios:device` で、作って入れて開く。

### S0 で決めたこと
- **型は手で書く。** OpenAPI の契約は型がゆるいので、コードを生成しない。
  - 文字列の値（役割・状態など）は、知らない値も壊さずに読む形（`OpenValue`）にした。
  - Web で `| null` の欄は null のまま書き戻す（`@Nullable`）。
- **見本のモードは、TS の規則をそのまま JavaScriptCore で動かす。** 規則を Swift に移すと、量が多く、ずれ続けるため。
- **絵（挿絵）の書き出しは S1 に回した。** 今日の画面と空の状態で初めて使うため。

### S1 で決めたこと
- **今日の画面の計算は Web の側で関数に分けた。** `src/domain/todayDigest.ts`（と `timeStrip.ts` の `stripLayout`）。Web の画面もそれを使い、Swift の `TodayDigest` は同じ答えになるかを、人・時刻・表示する人を変えた81の組で確かめる。
- **長さの数え方が2つある。** zod の検査（登録の名前・メールアドレス・パスワードの長さ）は Unicode のコードポイントで数え、パスワードの規則（`passwordProblem`）は UTF-16 で数える。Swift もそれぞれに合わせた（絵文字8つのパスワードは、zod では短すぎ、規則では長さが足りる）。
- **パスキーは画面に出さない。** 登録できるドメインができるまで、パスワードと確認コード（TOTP）でサインインする。パスワードの自動入力に対応した。
- **無操作の期限はアプリの側で案内する。** Web の IdleGuard と同じく、触れたら記録し、1分に1回だけサーバーに知らせ、60秒前に予告し、期限を過ぎたらサインアウトする。裏に回っている間は数えず、前に戻ったときに確かめる。サーバーの期限は変えない。
- **本人確認は `AppModel.run`。** REAUTH_REQUIRED と SESSION_EXPIRED を受けたら、入力中の画面の上でパスワードを聞き、同じ操作をやり直す（Web の `withReauthentication`）。
- **iPhone は下のタブ、iPad は横の一覧。** iPhone は今日・予定・タスク・メモと「その他」（Web の mobilePrimary と同じ選び方）。iPad はすべての機能を並べる。
- **日付と天気は画面の副題。** 上部のボタンの中に置くと、文字を大きくしたときに大きくならない（監査で分かった）。iPad では上のタブの帯があるので副題は出ず、今日の画面の見出しが日付を示す。
- **まだ作っていない画面**（予定・タスク・メモ・家計・アルバム・場所・ヒント・設定）は、作る段階を示す空の状態にした。設定は仮の画面（表示・接続先・サインアウト）。
- **サーバーの小さな変更:** 端末の名前（`server/auth/deviceLabel.ts`）、契約の cookie の名前を `__Host-fh_session` に直し、`audit-contract.mjs` が実装と照らす。`npm run dev:lan` を足した。

### S2 で決めたこと
- **カレンダーの計算は全部 Swift に移し、Web の答えで照らす。** 繰り返しの展開、月の表の段（`layoutLanes`）、時間軸の列（`layoutTimeline`）、予定の下書きと送る形（`EventForm`）、「すべて」の編集で日付を動かすときのずらし（`SeriesShift`）、公開範囲。乱数で作った70件の予定（終日・日をまたぐ・0時に終わる・繰り返し・例外日）を混ぜて確かめる。
- **変更の入力は「送らない」と「null で外す」を分ける。** `Patch`（keep・clear・set）で、Web の `location: '' || null` と同じ JSON を送る。試験は null と「項目がない」を区別して照らす。
- **シフト表の読み取りも Swift に移した。** 正規表現は JS の意味に合わせる道具（`JSText.swift`）を通す。位置と長さは UTF-16、`\s` と `\d` は JS の範囲、`$` は文字列の最後だけ。見本の表に全角・改行・月・人の違いを加えた261の組で、TS の `parseRoster` と同じ答えになる。記号と時刻の規則だけを端末（UserDefaults）に残す。
- **見本の仕組みに URL を足した。** JavaScriptCore には `URL` がなく、読み取りの URL の確かめがどれも「形が違う」になっていた。`src/native/nativePolyfills.ts` の `NativeURL` が、スキーム・名前とパスワード・ホスト・ポートをブラウザーと同じに分ける（`nativePolyfills.test.ts` で照らす）。国際化ドメインの変換はしない。
- **iPhone の月は月を縦に続け、日を押すと下からその日の一覧を出す。** iPad の月は表と、右にその日の一覧。iPad では矢印などのキーで日を動かせる。
- **曜日の行と日付の行は、本文の上に固定した。** 一覧の日付の見出しも流れる見出しにした。SwiftUI の留まる見出し（`pinnedViews`）は、アクセシビリティの監査で文字の大きさに付いていけないと出るため。
- **月の表の飾りは描く（Canvas）。** 日の見出し（日・祝日・¥）、段の上の予定、曜日の行は、読み上げを日のボタンの名前（「9月22日(火)、秋分の日、予定0件、支出あり」）と日の一覧で伝える飾りなので、文字の部品にしない（Web の aria-hidden と同じ）。部品にすると、狭いマスで切れる文字が監査で指摘される。
- **一覧は「さらに表示」を押したときだけ後の日を足す。** Web は画面の端に近づくと自動で足すが、アプリでは読んでいる途中に中身が伸びないようにした。
- **上に留まる帯は、監査で帯として扱う。** 識別子が `fixed-bar.` で始まる部品の下に隠れた本文は、ガラスのタブの帯と同じく、濃さを測らない（`ios/UITests/Audit.swift`）。
- **文字がとても大きいときは形を変える。** 操作の帯は本文と一緒に流し、前・今・次を見出しの下に並べる。週と日は時間軸に入りきらないので、日ごとの一覧にする。
- **保存していない入力の確かめは、Web と同じ文言の確認にした**（「入力中の内容を破棄しますか」）。iOS 26 の確認の一覧（confirmationDialog）は iPhone で「編集に戻る」を出さないので、アラートにした。
- **シフトと読み取りの保存は1行ずつ送り、行ごとに同じ冪等の鍵を使う。** 応答だけが届かなかった行を送り直しても、予定が2つにならない。
- **予定の場所は文字で入れる。** Web でも予定は場所の検索（openpoiapi）を使わない。場所の検索は S6 でメモ・家計・アルバムと一緒に作る。
- **日の一覧のタスクは表示だけにした。** その場で完了にする操作は、タスクの流れ（`todoFlow`）と一緒に S3 で作る（S3 で作った）。

### S3 で決めたこと
- **タスクとメモの計算は Swift に移し、Web の答えで照らす。** 一覧の絞り込みと並び順（同じ期限は名前の `localeCompare('ja')`。Swift は ICU の照合で比べる）、状態の流れ（見る人6通り×65件）、タスクとメモの下書きと送る形、メモの並び順と検索、添付の確かめ、大きさの書式（`toFixed(1)` の丸め方まで）、PDF の中のリンク。乱数で作ったタスク60件とメモ30件を混ぜる。
- **記録の間のつながり（関連づけ）は作らない。** Web にも画面がなく、Gateway と規則だけがある。使う画面ができるまで、アプリの Gateway にも足さない。
- **文字認識は、人が直す・入れるだけ。** サーバーも Web も自動では読み取らない。端末で読み取る（Vision）かどうかは、別に決める。
- **添付は、開くときに取って端末の一時の場所に置く。** `Caches/fh-attachments` に、ファイルの保護（`completeUnlessOpen`）をかけて置き、サインアウトと起動のときに消す。サーバーの署名つきの道は、同じサーバーのものだけを、同じセッションの cookie で取る。見本は `fh-sample://` を、アプリに入れたファイルにする。
- **PDF は PDFKit で全部のページを見せる。** Web の30ページの上限は、ブラウザーで描く重さのためなので付けない。中のリンクは http と https だけを開く。
- **保存は共有の画面から選ぶ**（「ファイルに保存」など）。Web はブラウザーの保存に任せる。
- **写真から添付するとき、HEIC は JPEG に、写真の動画は H.264 の MP4 にしてから送る。** サーバーは HEIC を断り、QuickTime はアプリの中で見られないため。
- **添付は1つずつ送り、ファイルごとに同じ冪等の鍵で送り直す。** 送れなかったものは、メモの画面を離れるまで残す。受け付けられたら、確認が終わるまで 2.5秒ごとに12回まで記録を取り直す（Web と同じ）。
- **タスクの状態の列は、空の列を出さない。** Web の板（4列）は横に並べるが、iPhone では縦に続くので、空の列を省いた。
- **今日の画面からタスクを開くと、そのタスクの内容を開く**（`AppModel.focus`）。
- **監査の「文字が切れている」の指摘のうち、括弧や中黒（（）「」・）を含む文のものは除く。** 日本語の組版はこれらの文字を詰めて組むが、監査は詰めを見込まずに幅を見積もる。撮影した画面で、全部見えていることを確かめた（`ios/UITests/Audit.swift`）。
- **読み上げの添付の名前は、拡張子を種類の言葉に置き換える**（「写真「教材の写真」を開く」）。拡張子つきの名前は、監査で読みにくい名前と指摘される。
- **オフラインのときに待ち行列へ入れる所（Web の executeQueueable）は、S8 で入れた**（「S8 で決めたこと」）。

### S4 で決めたこと
- **家計の計算は全部 Swift に移し、Web の答えで照らす。** 月の集計、費目別の割合（最大剰余法）、メンバー別、6か月の推移、残りのある負担、人ごとの正味と受け渡し、まとめた精算の要求、精算の履歴とまとめ、一覧の期間・絞り込み・並べ替え、支出の下書き・確かめ・送る形（変更の入力400通り）、精算額。乱数で作った80件の支出と、まとめた精算（生きている・まとめて取り消した・一部を個別に取り消した）を混ぜる。
- **送る本文の項目の順を揃える。** Swift の JSONEncoder は項目の順を決めないので、同じ入力でも送るたびにバイト列が変わることがある。サーバーと見本は冪等の鍵ごとに本文を照らすため、送り直しが「同じ鍵で別の内容」として断られる。本文は項目の名前の順で書く（`stableEncoder`）。
- **図は棒の行で描き、「表で見る」で表にもする。** 費目別・推移・人ごとの差し引きは、ラベルと金額を文字で示し、棒は飾りにする。Swift Charts の軸の文字は、文字の大きさに付いていけないため使わない。
- **押せないボタンは薄くしない。** 半分の濃さにすると文字が読みにくく、監査でも指摘される。控えめの文字の色と枠で示す（全部の画面のボタンに効く）。
- **まとめた精算は、見えない負担があると断られる。** 見本の碧さんには蓮さんの非公開の記録があるので、碧さんが「まとめて精算する」を押すと断られる（Web と同じ）。蓮さんなら記録できる（`SampleExpenseTests`）。
- **領収書の読み取りは、写真またはファイルから選ぶ。** HEIC は JPEG に変えて送る。読み取った内容は支出の入力に入れるだけで、保存は利用者が行う。
- **メンバー別の表は、人ごとの行にした。** 狭い幅で4列の表は読みにくいので、支払った額・負担する額・差を1人ずつ並べる。

### S5 で決めたこと
- **アルバムの計算は Swift に移し、Web の答えで照らす。** 一覧の絞り込み・並べ方（撮影日時の分からない項目は最後）、表紙、前後の移動と払い、スライドショーの項目、送信の確かめ・待ち行列・進み具合、入力、曲の音の並び（barNotes）。
- **送信は Web と同じく、分けて送り、途切れても続きから送る。** 枠を作り（POST /v1/uploads）、8MiB ずつ PATCH し、失敗したら HEAD で受け取られた位置を確かめて続きを送る。枠は `UploadTicket` が覚え、送り直しで枠を作り直さない（同時に送れる3件を使い切らない）。同時に3件、混み合っているときは2秒待つ。送り終えたら、確認の結果（追加・同じファイル・追加できない）が出るまでアルバムを読み直す。
- **写真の HEIC は、撮影日時や位置の情報を残したまま JPEG に変えて送る**（ImageIO で写す）。Web は HEIC を断るが、iPhone の写真はほとんど HEIC のため。位置を残すかは、これまでどおり「撮影場所を残す」でサーバーが決める。
- **動画は H.264 の MP4 にしてから送る。** 撮影日時の情報は残す。縮小画像（長い辺 640 の JPEG）は端末で作り、送り終えてから付ける（Web と同じ）。
- **写真や動画は、同じセッションで取ってから見せる。** サーバーの写真の道はセッションの cookie が要る。取ったファイルは添付と同じ一時の場所に置き、サインアウトと起動で消す。見本の写真は、Web の見本の SVG と同じ色と形を Swift で描く。見本で送ったファイルは、記憶の中の見本と一緒に端末の一時の場所に残す。
- **曲は AVAudioEngine で合成する。** 音の並び・立ち上がり（0.04秒）・指数の減衰・低域通過のフィルターは Web と同じ。音の処理の糸から呼ばれる部分は、主の糸に縛らない場所で作る（Swift 6 が呼ばれた糸を確かめて止まるため）。
- **「動きを減らす」がオンなら、スライドショーの写真をゆっくり拡大しない。**
- **読み上げの名前は、ファイルの拡張子を外す**（「写真「item-sports-1」を開く」）。
- **一度にまとめて端末に保存（Web の「すべて端末に保存」）は作らない。** 1つずつ共有の画面から保存する。iOS では、まとめて保存すると写真の許可を何度も求めることになるため。

### S6 で決めたこと
- **場所の計算は Swift に移し、Web の答えで照らす。** 場所のキー（FNV-1a）、支出とメモからのまとめ、並べ替え、距離の表示、丸めた位置、候補の並べ替え、記録用の形、通知の予定（notificationPlan）、検索の結果のまとめ。
- **外部の場所検索（OpenPOI API）は、Web と同じ同意を得てから使う。** 送るのは小数第3位に丸めた位置か検索語だけで、cookie・リファラー・キャッシュを使わない専用の接続で送る。同意は家族のサーバーのプライバシー設定に残す（版が変われば取り直す）。現在地は CoreLocation で1度だけ、写真の位置は ImageIO で端末の中で読む。試験では外部へ送らない（手入力で確かめる）。
- **ヒント・検索・通知の行き先（/tasks/<id> など）は、アプリの画面と開く記録に読み替える**（`Router`）。
- **検索は上部の虫めがねから開く。iPad では ⌘K でも開く。** 画面を開く・記録を追加する操作も、同じ画面に並べる。
- **すぐに追加は上部の「＋」から、種類を選んで開く。** 入力の画面は、それぞれの画面の追加と同じもの。
- **この端末への通知は、利用者が通知の一覧で「この端末にも通知する」を選んだときだけ予約する。** Web にはない（ブラウザは通知を出さない）。家族の通知の一覧と、記録から作った予定を合わせ、通知の好み・夜間（21時〜翌7時は7時にまとめる）・止めた通知・内容を隠す設定に従う。サインアウトで、予約も届いた分も消す。端末の通知を押すと、その記録を開く。
- **通知の好み（タスク・予定・夜間）を変える画面は、設定（S7）で作った。**
- **Form の Section に付けた sheet は効かない。** 場所の選び方の画面は、行に付けて開く。

### S7 で決めたこと
- **設定の12のタブは、Web の `settingsTabs.ts` を書き出して使う**（名前・説明・表示に要る能力。`Copy/settingsTabs.settingsTabs.json`）。iPhone は一覧から押して進み、iPad は左の一覧と右の中身の2列にする。ヘルプの「関連する設定」は、同じ設定の中のタブを開く。
- **設定の規則は Swift に移し、Web の答えで照らす。** 家族の人数と名前の変更の回数、退出できるか（ただ1人の管理者は退出できない）、役割ごとの能力と個別設定（乱数で作った80通り）、変更の記録の条件（期間を日付の範囲に）と日ごとのまとめと開く画面、記録の項目名、ヘルプの絞り込み（NFKC と小文字）、色のリストと家族の名前の確かめ（長さは zod と同じくコードポイントで数える）。
- **サーバーが返す値で文言を引く表（記録の項目名・種類・対象、役割、利用の状態、リンクの種類）は、文言の書き出しで辞書も作る**（`table`）。
- **パスキーの追加は、アプリとサーバーのドメインの設定（webcredentials）ができるまで出さない。** `FH_ASSOCIATED_DOMAIN`（Info.plist の `FHPasskeyRelyingParty`）が空なら、Web で追加したパスキーを表示するだけにする。使うときは、entitlement の associated-domains に `webcredentials:<ドメイン>` を足し、サーバーに AASA を置く。作成の条件と応答の変換（base64url、RegistrationResponseJSON）は Web の `browserPasskeyOptions`・`serializeRegistration` と同じ形で、試験で確かめる。見本では Web の見本と同じく「デモ登録」にする。
- **確認コードの設定では、設定用の文字列を QR コードでも出す。** 同じ端末の認証アプリで開く入口も置く。回復コードは1回だけ出し、閉じるまで画面を閉じられない。
- **アイコンの画像は、端末の中で 192px の正方形の JPEG に縮めてから送る**（Web と同じ。元の写真の位置情報は送らない）。
- **「隠れている間は画面をぼかす」は、アプリの切り替えの画面とほかのアプリに移っている間にぼかす。** 「動きを減らす」は、端末の設定かアプリの設定のどちらかで、画面の動きを止める。表示の密度「コンパクト」は、カードの余白と一覧の節の間を詰める。どれもこの端末だけの設定（UserDefaults）。
- **接続先（見本・サーバー）を選び直す入口は「サインインとセキュリティ」に置く。** 見本では「通信が切れた状態を試す」も置く（Web の見本の offline の場面と同じ。次に家族の記録を読み込むと戻る）。
- **設定のタブの中身は、一覧（Form）ではなくカードを縦に並べる**（アプリのほかの画面と同じ形）。一覧で作ると、アクセシビリティの監査が、最初に監査した一覧の画面の中ほどの行の文字の大きさと濃さを測り損ねた（どのタブでも、最初の1つだけ。順番を変えても、前に監査を1回流しても変わらなかった）。設定の項目の一覧と、入力のための画面（権限・パスワード・確認コードなど）は一覧のまま。節の見出しはテーマの文字の色で書く（システムの見出しの色は濃さが足りなかった）。
- **Form の節に付けた sheet と alert は開かない**（S6 と同じ）。色のリストの画面と確認は、いつもある行やボタンに付ける。
- **家族グループの名前は、「名前を変更」から開く小さな画面で変える。**

### S8 で決めたこと
- **送れなかった変更（Web の executeQueueable）を入れた。** 予定・タスク・メモの追加と変更（文字認識の直しを含む）が、つながらずに断られたときだけ、未送信の変更としてこの端末に置く。家計・精算・削除は、つながっているときだけ行う（Web と同じ）。
  - 中身は CryptoKit の AES-GCM で暗号にする。鍵は Keychain に「この端末だけ・ロック中は読めない」で置き、記録は Application Support に完全な保護をかけ、バックアップから外す。誰の・どの家族の・どの権限の版の変更かは暗号の追加データにして、書き換えると読めなくする。
  - 50件まで、24時間で消える。接続が戻っても自動では送らない。画面の下に「未送信の変更が N 件あります」を出し、確かめてから1件ずつかまとめて送る。版の競合は「内容の確認が必要」、権限や対象がないときは「権限の確認が必要」にして残す。送り直しは最初に送ったときと同じ冪等の鍵を使う。
  - 別の人・別の家族の変更が残っていたら、送らずに消す。サインアウトしても残す（Web と同じ。もう一度サインインすると送れる）。
  - 送れなかったメモに付けようとした添付は送らない（メモが届いてから付ける）。
- **文字を最大にした（アクセシビリティの最大）ときも、今日・タスク・メモの画面を監査にかける**（`S8UITests`）。VoiceOver の読み上げの名前は、各段階の監査と UI の試験で確かめている。
- **iPad の3列は、横の一覧（タブの帯を横に開いたもの）と、各画面の一覧と内容の2列で作る。** 予定・タスク・メモ・家計・設定は、iPad では一覧と内容を並べる。`NavigationSplitView` の3列には作り直していない（タブの帯と二重になるため）。
- **使い方の一覧（`docs/verification/use-cases.json`）に、アプリで確かめる使い方（products の I）を足した。** I の使い方は、`ios/` の試験を名指しする（`scripts/check-use-cases.mjs` が確かめる）。
- **配布と課金の論点は `docs/legal/ios-distribution.md` にまとめた**（弁護士の確認ではない）。
