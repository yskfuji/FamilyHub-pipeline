# 見た目のトークン

段階7で作った見た目の土台。値は `src/design-system/tokens.css`（既定の昼 `:root`、標準の夜 `dusk`、夜に共通の影）と `src/design-system/themes.css`（抹茶・桜・紅葉・川の昼と夜）にある。色は16進数で持ち、試験もその値で行う。OKLCH は、色を導いた過程の記録だけに使う（[criteria.md](../acceptance/criteria.md) A11-1）。

## 確かめ方

| 何を | どこで | 基準 |
|---|---|---|
| 宣言した文字と面の組（全10テーマ） | `src/design-system/themes.test.ts` | 4.5:1 以上。丸めない。例外なし |
| 部品の境界・フォーカス・図表の色 | 同上 | 隣り合う面と 3:1 以上（WCAG 1.4.11） |
| 実際の画面の文字 | `e2e/contrast.spec.ts`（`npm run audit:contrast`） | 祖先の背景を透明度ごと重ねて 4.5:1（大きな文字は 3:1）。::placeholder も測る。axe の incomplete は失敗 |
| 文字の大きさ・余白・動きの時間 | `scripts/audit-css.mjs`（`npm run audit:css`） | 尺度のトークンだけ。名前を付けた例外だけ許す |
| JS と書体の量 | `e2e/real/performance.spec.ts`（`test:real` の一部） | 主要5画面で、LCP より前の JS が gzip -6 で 150,000 バイト以下、woff2 が 400,000 バイト以下 |

### 書体（測って選んだ）

主要5画面を、実際の API と `dist-http` にサインインした状態で、空のキャッシュから開いたときに読む woff2 のバイト数（`e2e/real/performance.spec.ts` と同じ測り方。種のデータ）:

| 画面 | 前（Noto Serif JP 可変 + Noto Sans JP の latin） | (a) Noto Serif JP 600 の静的な部分ファイルだけ | (b) システムの明朝 + SVG の名前 |
|---|---|---|---|
| 今日 | 440,956 | 278,924 | 25,040 |
| 予定 | 311,420 | 191,236 | 25,040 |
| 家計 | 436,920 | 273,024 | 25,040 |
| アルバム | 298,112 | 189,388 | 25,040 |
| メモ | 400,764 | 254,376 | 25,040 |
| 5画面を続けて開いたとき | 636,756 | 403,528 | 25,040 |

- (a) は1画面では 400KB に収まるが、5画面を続けると 403,528 で超える。読む部分ファイルは見出しの字によって変わり、記録が増えた全体の試験では、前の値で家計が 501,304 まで増えた。
- **(b) を選んだ。** 見出し（h1・h2・金額・月の見出し・アルバムの題名・頭文字）は `--font-serif`（Hiragino Mincho ProN → Yu Mincho → Noto Serif JP / Noto Serif CJK JP（入っていれば）→ serif）。ブランドの名前「よりどころ」は、Noto Serif JP Bold（SIL Open Font License 1.1）の字形を書き出した SVG（`src/design-system/wordmark.ts`）にし、どの端末でも同じ形で出す。柿の印はそのまま。
- 明朝の @font-face の一覧も CSS から消えた（index の CSS が約 49KB から約 14.5KB（gzip）に減った）。
- 本文の日本語は前と同じく端末のゴシック（Hiragino Sans、Yu Gothic UI など）。前は Noto Sans JP の latin の部分ファイル（25,040 バイト）だけを読んでいた。
- **(c) 2026-11-07 に、latin の部分ファイルもやめた。** モバイルの LCP（Lighthouse の模擬の 4G）で、最初の表示の前に読むバイト数がほぼそのまま時間になり、この 25KB で約 140ms 遅れていた（`docs/audits/lcp-assessment.md`）。本文の英字と数字も端末のゴシックで出す。Android の端末のゴシック（Noto Sans CJK）は、もとの書体とほぼ同じ字形。変わるのは iOS（Hiragino Sans）と Windows（Yu Gothic UI）の英字と数字の形で、大きさと行間はトークンで決まるので配置は変わらない。今は woff2 を1つも読まない。
- 端末に明朝がないとき（Android の一部、Linux）は、見出しはその端末の serif かゴシックになる。字の形は変わるが、大きさと行間はトークンで決まるので、配置は変わらない。

## 余白・角丸・影・動き・重なり

- 余白 `--space-1`〜`--space-8` = 4/8/12/16/24/32/48/64px。ページの最後に空ける高さ（下のナビとすぐに追加のボタンの分）は `--layout-page-end`（7.5rem）。前の rem の値は、いちばん近いトークンに寄せた（同じ距離なら大きい方）。
- 角丸 `--radius-xs` 6px・`-sm` 10px・`-md` 18px・`-lg` 28px・`-pill`。
- 影 `--shadow-1`（カード）・`-2`（固定の部品）・`-3`（ダイアログ・ドロワー・検索・知らせ・警告）。夜のテーマでは黒い影が見えにくいので、1px の明るい縁（白 5〜9%）を重ねる。
- 動き `--duration-1`〜`-5` = 100/150/200/250/300ms、`--ease-standard`・`--ease-enter`・`--ease-exit`。前は 120/180/260ms。300ms を超えてよいのは、スライドショーの写真の拡大（6s）と、読み込み中の骨組み（1.4s の繰り返し）・帯（1.1s の繰り返し）だけで、どれも `scripts/audit-css.mjs` に名前と理由がある。動きを減らす設定では止める。
- 重なり `--z-raised`〜`--z-skip`（1〜1000）。
- 固定の部品の高さ（段階8）: `--layout-topbar` 5.25rem・`--layout-topbar-compact` 4.4rem（下のナビがある幅。段階12から `width < 42.7rem`）・`--layout-bottom-nav` 4.6rem・`--layout-fab` 3.25rem・`--layout-fab-bottom` 5.5rem。`html` の `scroll-padding-block` に使い、Tab で焦点が動いたときに上部・下のナビ・すぐに追加の下へ隠れないようにする（WCAG 2.4.11）。
- 重ね表示の動き（段階8）: ドロワーは右から `--duration-3`（200ms）、narrow のシートは下から 200ms、ダイアログは `--duration-2`（150ms）。どれも `transform` だけを動かし、透明度は動かさない（濃さの確かめが途中の値で崩れないように）。画面の切り替えは View Transitions（本文の入れ替え 150ms、題名の移動 200ms）。動きを減らす設定（端末とこの端末の設定のどちらでも）では View Transitions を呼ばず、CSS の動きも止める。
- 押したときの反応（段階8）: ボタン・ナビ・一覧の項目は `:active` で縮むか地の色が変わる。押した瞬間は遷移させず（`transition-duration: 0s`）、次のフレームで変わって見えるようにする。

## 画面分割（段階8）

段階は本文の領域 `#main` の幅で決める（`src/design-system/sizeClass.ts`。`html` の `data-size-class` にも書く）。

| 段階 | #main の幅 | 詳細の出し方 |
|---|---|---|
| narrow | 600px 未満 | 全画面のシート（`.drawer[data-presentation='sheet']`） |
| medium | 600〜1100px | 右からのドロワー |
| wide | 1100px 以上 | 一覧の横に詳細を並べる（タスク・メモ・家計・場所。`DetailSurface`） |

- 下のナビとレールの切り替えも段階にそろえた（段階12）。レールは、置いたときに本文が 600px 以上になる窓の幅（600px ＋ レールの 5.2rem = `42.7rem`）から出し、下のナビがある間は #main の幅によらず narrow とする（`src/design-system/sizeClass.ts` の `BOTTOM_NAV_QUERY`。CSS の `@media (width < 42.7rem)` と同じ）。前は窓の 760px で切り替えていたので、600〜760px の窓が「下のナビと medium のドロワー」の組になっていた。レールがあるのに #main が 600px に届かない（縦のスクロールバーの分など）ときは medium。LAYOUT-6 が 560〜1280px の9つの窓で、下のナビが出ていることと narrow が一致することを確かめる。
- 予定の月の表と日の欄の2列は、窓が `49rem` 未満では1列にする（レールのある狭い medium でマスが 39px になっていたため）。
- `#main` に `container-type` を付けないのは、付けると中の `position: fixed`（予定の日のシートなど）の基準が `#main` に変わるため。段階は JavaScript の ResizeObserver で測る。
- すぐに追加は、下のナビがある幅では右下に浮かべ、レールのある幅では上部の操作の並びに置く（本文の上に重ならない）。

## 画面の地

前は、画面の地（body）に柿と藍の放射状の色むらを重ねていた。上にのる文字の濃さを確かめられず（axe は incomplete になる）、淡い文字の比も下げていたので、紙の色だけにした。

## 濃さの確かめで直したこと

- 上部・左のレール・下のナビは、半透明の地にぼかしを重ねていた。下を流れる写真によって文字の比が変わる（アルバムで、写真が黒いと下のナビの文字が 4.5:1 に届かない）ので、不透明の地にした。
- メンバーの頭文字は、メンバーの色の上に、昼は白・夜は紺の文字をのせていた。夜のテーマで 2.7〜4.0:1 だったので、色ごとに白と黒の比の大きい方（`src/domain/readableText.ts`。どの色でも 4.58:1 以上）にした。
- 写真・動画・添付の表示画面の上の帯は、下へ薄くなる重ねだった。明るい写真の上では件数や撮影日時が 1.1:1 になる（段階9で表示画面を撮影一覧に足して見つかった）ので、同じ濃さ（`rgb(5 9 13 / 82%)`）の帯にした。狭い幅では、題名（撮影日時・添付の名前）を操作の下の行に回して切らずに出す。
- サインインと初期設定の左の帯の小さな見出しは、昼の色 `#ed9e7b` を直書きしていた（夜のテーマでは帯が明るくなり 1.7:1）。`--on-accent` にした。

## 挿絵（段階10）

`src/design-system/illustrations/` に、手で書いた SVG を置く（ほかのライブラリ・素材・アプリの絵は使わない）。空の状態10種（予定・タスク・メモ・家計・アルバム・場所・検索で見つからない・オフライン・エラー・全部済んだ）、はじめにの3場面（家族・共有範囲・ようこそ）、今日の画面の季節の4場面。

- **形**: 丸みのある地（`Ground`）の上に、角を丸めた単純な形を1〜3個置く。線の端と角は丸める。柿の実（へたと実。`Kaki`）と人の形（`Person`）を共通の部品にし、ブランドの柿の印と同じ温かさにそろえる。
- **線**: 太さは表示の大きさに関係なく `vector-effect: non-scaling-stroke` で決める。空の状態 2px、小さな空の状態（検索の重ね表示・今日の欄の中）と季節の場面 1.75px（アイコンと同じ）、はじめに 2.25px。
- **色**: テーマの変数だけ。輪郭 `--ink-soft`、面 `--sheet`、塗り `--brand-soft`・`--moss-soft`・`--info-soft`・`--attention-soft`、差し色 `--brand`・`--moss`・`--gold`・`--accent`、細部 `--line-strong`。地は新しい `--art-ground`（昼は `--paper-deep`、夜は `--info-soft`。夜に `--paper-deep` だと面より暗い穴に見えたため）。10テーマで色が変わることは `e2e/illustrations.spec.ts` の ILLUS-3 が、描いた結果の色がすべてテーマの変数の値であることで確かめる。
- **読み上げ**: どれも飾り。`aria-hidden="true"` と `focusable="false"` を付け、`<title>`・`role`・`aria-label` は書かない。意味は隣の見出しと文が伝える。挿絵は文字を持たず、意味を伝える部分もないので、濃さの基準（1.4.11）の対象外（`e2e/contrast.spec.ts` は挿絵の隣の文字を、ほかの文字と同じく 4.5:1 で測る）。
- **大きさ**: 1つのファイル（共通の部品を含む）が gzip で 4,096 バイト以下。`scripts/audit-illustrations.mjs`（`npm run audit:illustrations`。`verify` に入れた）が、大きさ・色の直書き（16進数・rgb()・hsl()・色の名前）・`aria-hidden` と `focusable` の抜け・`<title>` を失敗にする。描いた結果も `illustrations.test.ts` で同じことを確かめる。
- **読み込み**: 挿絵は使う画面の部品から読み込む（`EmptyState` の `illustration` に渡す）。最初に読む JS に入るのは、経路のエラー境界と「接続できません」の画面の2つ（どちらも gzip で約 0.5KB）。
- **動き**: 季節の場面だけ、表示したときに 300ms（`--duration-5`）で 4px 上がる。transform だけで、動きを減らす設定（端末とこの端末のどちらでも）では動かさない。

時刻の帯（朝6時から夜まで。予定は長さのある帯、期限のタスクは点、今の時刻は縦の線。下の一覧と同じ内容なので読み上げない）と、5つの欄「次にすること・時刻順に確認・期限（自分の担当）・天気・家計の一目」。並びは画面の段階で変える（読む順と見た目の順は同じ）。

## 図表（段階11）

`src/design-system/charts/` に、手で書いた SVG の横棒を置く（図表のライブラリは使わない。部品は家計とヒントの画面が共有する1つの塊で、gzip -6 で約 1.5KB）。費目の内訳（1系列の横棒）、6か月の推移（支出と収入の2つの面）、人ごとの差し引き（中央から左右の棒）、ヒントの日ごとの件数（予定とタスクを日ごとに並べる）。根拠は Cleveland と McGill 1984、Heer と Bostock 2010（計画 B の「図表」）。

- **表し方**: 値は位置と長さだけ。円・扇形・面だけの表し方は使わない（CHART-5 が、SVG に rect・line・text 以外がないことを確かめる）。軸は必ず 0 から（`scale.ts` の `lengthScale`・`divergingScale`。位置は 0.01% に丸める）。費目は多い順、推移と日ごとは時間の順。
- **棒**: 太さ 12px（24px より細く、行の残りは空ける）。データの端だけ角を 4px 丸め、0 の側は角を立てる。目盛りの線と格子は引かない。0 の位置は棒の始まりがそろうことで示し、左右の棒だけ中央に1本の線（`--line-strong`）を引く。
- **文字**: 値は棒の先に直接書く（`formatYen` と件数。費目は割合も）。値の文字の幅は `--layout-chart-share`（8rem、金額と割合）・`--layout-chart-yen`（5rem）・`--layout-chart-count`（3rem）として棒から空け、文字を縮めたり切ったりしない。左右の棒は、棒のない側の中央の脇に「受け取る ¥250」「支払う ¥250」と書く。名前の列は `--layout-chart-name`（3rem）と `--layout-chart-name-wide`（5.5rem、日付）。文字の色は `--ink`、0 と割合は `--ink-soft`、今月・今日の印は `--brand`。棒の色を文字に使わない。
- **色**: `--chart-1`〜`--chart-6` だけ（`data-tone`）。出ていくお金は `--chart-1`（橙）、入るお金は `--chart-4`（青）、予定は `--chart-2`、タスクは `--chart-6`。系列の名前（支出・収入・予定・タスク・受け取る・支払う）を必ず文字で添えるので、凡例を置かず、色だけに頼らない。強制色のモードでは棒を `CanvasText` にする。
- **推移を2つの面に分けた理由**: 支出と収入を1つの尺度にすると、見本のデータでは支出（¥12,060）が収入（¥320,000）の4%の長さになり読めなかった。どちらも 0 からの別の面にし、説明文に「それぞれの最も多い月を同じ長さにして描いています」と書く。
- **表**: どの図表にも同じ数値の表を「表で見る」（`chart.table.*`。`aria-expanded`・`aria-controls`）で開いて添える。表は `caption` と `th scope` を持ち、閉じている間は `hidden`。図表は `role="img"` と短い要約（aria-label）で、中の SVG はすべて `aria-hidden`。費目の内訳だけは行がその費目の一覧へのリンクなので `role="img"` を付けず、リンクの名前に金額と割合を入れる。
- **少ない記録**: 推移は記録のある月が2か月に満たなければ、空の軸を描かず「記録のある月が2か月以上になると…」と1文で伝える。日ごとの件数は7日がすべて0件なら同じく1文。差し引きは残りがなければ前の「支払いが残っている人はいません。」のまま。
- **幅**: 幅は SVG の幅に対する割合で描くので、3つの画面の段階と 320px で横にはみ出さない（CHART-6 が、文字が画面の中にあり、重ならず、棒の上に乗らないことを確かめる）。
- **動き**: 表示したときに 300ms（`--duration-5`）で棒が伸びる（transform だけ）。動きを減らす設定（端末とこの端末のどちらでも）では動かさない（CHART-8）。

## 操作の大きさ（段階12）

- `--layout-target` 2.75rem（44px）・`--layout-target-primary` 3rem（48px）。タッチの配置（`html[data-size-class]` が narrow と medium）では、操作できる要素がすべて 44×44px 以上、主な操作（`.button.primary`・すぐに追加）は高さ 48px 以上。wide では 24px 以上。文の中のリンクは除く（WCAG 2.5.8 の例外）。
- `.button` と切り替えのボタンは幅も 44px を下回らない。文の外に1つだけ置くリンク（今日の「カレンダーへ」、位置情報の規約と出典、管理の見本の「開く」）は `.standalone-link` で押せる範囲を 44px にした。一覧の行の右のボタンは折り返さない（「無効にする」が 34px の幅で縦に折れていた）。
- LAYOUT-1 が全画面（設定の12のタブを含む35の経路）× 4つの窓（390・834・700・1440px）、LAYOUT-2 が重ね表示（詳細のシートとドロワーと横の詳細、すぐに追加、支出、検索、通知、権限、パスワード、まとめて精算、アルバムの編集、その他のメニュー）× 3つの段階で確かめる。チェックボックスとラジオはラベルの大きさで測る。

## 文字の間隔（WCAG 1.4.12、段階12）

LAYOUT-3 が全画面 × 3つの段階で、行間 1.5・字間 0.12em・語間 0.16em・段落の後 2em を `!important` で当て、はみ出しを隠す要素で文字が切れていないこと（`scrollWidth`・`scrollHeight`）（文字の箱が、はみ出しを隠す祖先の外へ 2px を超えて出ていないか。飾りのはみ出しは数えない）と、文字の箱が重ならないことを確かめる。省略記号で切る文字は、同じ文字が `title` か読み上げの名前にあるときだけ許す（月の表の祝日名は `title`、週の表の予定は「09:30〜11:30 学校公開を開く」）。直したもの: 週と日の表の予定の文字（切っていた → 省略記号）、週と日の見出し（折り返さずに隣のボタンへ重なっていた → 折り返す）、ヘルプの分類のボタン（390px で縮めて重なっていた）、ようこその見本のカード（位置を固定して重ねていた → 流れに置き、飾りの円は自分の箱で切る）、WebKit の招待の一覧（本文と操作の2つだけの行は、操作の列を中身の幅に）。

## フォーカス（段階12）

- Tab で焦点が動いたら、要素を全部見せる（`src/design-system/revealFocus.ts`）。横にスクロールする並びの中では並びの中に（Chromium は一部だけ見えている設定のタブへ Tab で移ってもスクロールしなかった）、縦は窓の上下（重ね表示の外では上部と下のナビ・すぐに追加の scroll-padding を除く）で切れているときだけ近い側へ寄せる（WebKit は、アカウントのメールアドレスの欄や詳細の欄の下の欄で、半分が窓の外のまま止まっていた）。プログラムで焦点を移すとき（`preventScroll`）は動かさない。
- 日付と時刻の欄は、焦点が中の年・月・日と暦のボタンに入り、暦のボタンのときは欄が `:focus` にもならないので、`:focus-within` で欄の輪郭を出す。
- LAYOUT-5 が設定の12のタブと重ね表示（narrow と wide）、横にスクロールする並び（設定のタブ・週の表・アルバムの絞り込み）で Tab を送り、輪郭が 2px 以上で地との比が 3:1 以上、窓（固定の部品の分を除く）とはみ出しを隠す祖先の中に押せる大きさ（44px か要素の大きさ）が見えていて、見えている部分の中心と内側の四隅の5点のどれかが `elementFromPoint` で焦点の要素に当たる（全部が覆われていない。WCAG 2.4.11）ことを確かめる。
